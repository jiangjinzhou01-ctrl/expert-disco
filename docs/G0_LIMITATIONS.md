# G0 限制

本报告与最终测试结果一同交付；具体通过与未执行项见验收表。

## 支持范围

- 仅一对固定矩形门，门仅允许平移和绕世界 Y 轴旋转。无缩放、镜像、倾斜、滚转或局部重力。
- 两个简单灰盒房间、一个运动学胶囊玩家，世界重力固定为 -Y；不包含跳跃、大型可移动物体跨门或刚体切片。
- 目标门表面在离屏 pass 中隐藏，限制为一层真实目标世界；不支持递归传送门。
- 无正式前厅、INVERT/ECHO/DRIFT 世界、音频系统、账户或多人系统。
- WebGL 2 是运行前提。未提供非 WebGL 静态模式替代核心交互。

## 视觉与生命周期

真实浏览器覆盖固定Chromium中的正面、30°/60°斜角、1m/0.1m/5mm、门框边缘与跨面状态。验证没有证明所有GPU/浏览器组合均相同；尚未覆盖的Safari、Firefox和真实手机列为限制，不能扩大为“所有浏览器正常”。

单层屏幕采样 RT 的质量取决于设备 DPR 与质量系数。RT 分辨率降低可能使门内几何边缘略软，不能将采样误差与空间映射错误混为一谈。无阴影、复杂后处理或大型装饰，目的为保留核心性能预算。

最终生产JS约5.51MB，gzip约1.99MB，Rapier compat包含WASM数据；尚未拆包优化加载，构建保留体积warning，移动网络首屏预算需要进一步验证。

GPU 时间当前未采集，面板明确显示N/A；即使扩展存在也不以CPU耗时冒充。Three 资源统计是已知几何/纹理/程序数量，不是精确显存字节数。

## 设备与性能覆盖

真实中端/高性能 Android 设备未连接，真实手机十分钟连续运行、热稳定性、前后台切换、持续 P95≤33.3ms 和实际触控舒适度均为 **BLOCKED / 未通过验收**。模拟移动视口或触控事件的 Chromium 结果不能替代真实设备结果。

桌面自动化所用 headless Chromium 与 SwiftShader 数据仅代表该 Linux 软件渲染环境，不应外推为主流桌面 60FPS 或手机 30/60FPS。最终实测数据和采样长度见技术报告。

## 进入 V1 前的扩展

V1 需要在保持纯数学、渲染和传送所有权边界的基础上，补齐真实硬件覆盖和性能预算、可复用世界生命周期、检查点与错误恢复策略、输入可访问性和更多场景资产。若未来支持移动门、倾斜门、物体跨门、局部重力或多门递归，应分别扩展数学、渲染和物理协议并增加测试；G0 的限制不能被当作这些行为已受支持。

当前建筑碰撞体全部为cuboid，源门背面支持平面判定也只覆盖cuboid。未来新增非cuboid源门背面形状时需要扩展其support-plane判断；目标完整胶囊重叠与扫掠不放松。

源碰撞若使平面前段未能到达门面，本物理步的剩余时间保守停止，下一60Hz步继续求解；这只适用于尚未成功跨面的情况。成功跨面仍完整映射原始剩余位移，并由目标区域处理，不能丢弃该目标段。

出口剩余路径如果即将碰到墙或障碍，G0保守拒绝整次传送；未实现允许先穿越再在目标侧滑动到碰撞点的更宽松策略。

最终建议以技术报告为准。硬件性能缺口必须补齐后才能将G0判为全部通过；现有模块可用于继续G1工程验证，不能视作V1已完成的生产级保证。
