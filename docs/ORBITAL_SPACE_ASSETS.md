# Orbital vista assets and implementation

The orbital vista is an authored composition around the VESTIBULE, not an astronomically scaled model of the solar system. All nearby and distant bodies are real sphere meshes, with a real ring mesh on the primary body. The deterministic background stars are geometry points generated by THRESHOLD, not a video or static portal texture.

## Integration

```ts
const orbital = await loadOrbitalSky(import.meta.env.BASE_URL, world.offset);
scene.add(orbital.group);
// Once per existing ExperienceLoop/ChapterRuntime frame:
orbital.update(elapsed, controller.state.returned);
// On scene disposal:
orbital.dispose();
```

Use the existing single application render loop. Increase the main perspective camera far plane to at least 1500 so the points at radius900 remain visible; the virtual portal camera copies the same projection. A near-black A background (`#020711`) gives appropriate contrast. Orbital materials deliberately bypass the architectural distance fog and retain Three global clipping-plane support, so target scene exit clipping works during a portal pass. No extra lights, shadow maps, render targets, render passes, physics changes or animation loops are created by this module.

Positions are local to VESTIBULE and shifted by the supplied world offset. The primary body is at `(-105,104,-222)`, radius64; ring radii78.72–143.36. Smaller bodies surround the room, including bodies on its reverse side for free-look and return travel. The baseline solid roof and walls may occlude these real objects; glazing/ribs replacing inaccessible roof surfaces belongs to the architectural integration.

## Budget and rendering

- 11 bodies: one primary ringed planet, three mid-scale bodies, seven more distant bodies.
- 1900 seeded stars, fixed seed`0x7a12a95`.
- 30,704 authored triangles over all planet/ring/atmospheric geometry.
- Five 2k texture files,2,258,031download bytes total. These files are ordinary JPEG/PNG with generated GPU mipmaps; they are **not** claimed to be GPU-block-compressed KTX2.
- Day/night shading uses world-space diffuse illumination and a low night-side bounce.
- The primary ring casts an analytic shadow onto the planet; the planet casts an analytic shadow onto the ring. These analytic local shadows do not allocate shadow maps.
- Transparent atmospheric shells provide a narrow limb. There is no volumetric raymarching or expensive full-screen postprocessing.
- Texture resources and geometry are allocated once, reused each frame and disposed idempotently.

## Actual isolated verification

Chromium158.0.8127.18 with headless SwiftShader, viewport1280×720,DPR1. An isolated scene was rendered with the actual module and actual local textures. The captured view used eye`(0,1.55,33)`,lookAt`(-55,50,-200)`,FOV50°,far1500.

- Five source files decoded successfully and their dimensions were verified with Pillow.
- TypeScript check initially passed before parallel UI/streaming integration began; the module's ESLint check passed.
- Initial visible render:8draw calls,17,024visible triangles,1900points. This is a draw count, **not** a GPU timing or device FPS claim.
- Real-time rotation changed from1.519rad at17s to1.54rad at20s.
- Shader compile/page error list was empty.
- Screenshot `/tmp/threshold-orbital-sky.png` was visually inspected.
- Further global-clipping and zero-resource disposal assertions are recorded in `/tmp/threshold-orbital-sky-verification.json` when running the isolated verification.

This verification does not establish final architectural visibility, mobile hardware performance, or the full portal scene's visual acceptance. Those depend on integrated application checks.
