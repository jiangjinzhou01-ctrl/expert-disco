# 真实手机十分钟采集流程

当前没有连接真实 Android 设备，以下是可复现操作入口，**不是已执行记录**。验收表中相关项目保留 BLOCKED。

## 环境记录

记录手机型号、SoC、RAM、Android版本、浏览器精确版本、屏幕方向/分辨率、DPR、供电状态、是否节能、室温与网络地址。设备通过局域网访问开发服务器，或将普通 `dist/` 放置于可访问的静态站点；不要以浏览器模拟设备结果代替真机。

```bash
npm ci
npm run dev -- --host 0.0.0.0
```

手机访问 `http://<主机局域网IP>:5173/?debug=1`。如果调试远程设备，使用已授权的浏览器远程调试连接；本工程不需要登录外部服务。

## 测试操作

1. 横屏进入，确认左区移动、右区观察和两指同时操作。记下初始RT尺寸、质量、几何/纹理/程序数量、当前世界与事件编号，导出启动诊断JSON。
2. 前一分钟暖机：缓慢接近A门，左右平移核对门内视差，转动视角，进入B并自然回头返回A。不得使用测试瞬移。
3. 从暖机结束开始计时十分钟。每分钟至少一次A→B→A，轮流贴近左右门框，持续转动视角。保持可恢复的正常运动，不改变源代码。
4. 在第0、1、3、5、10分钟导出诊断JSON。记录每次事件编号、当前世界、FPS、平均/P95/P99帧时间、物理耗时、RT尺寸和资源数量。面板统计为有限滚动窗口，不能把最后一个窗口当作全部十分钟分布；用各窗口及资源趋势共同评估。
5. 第3分钟切后台约15秒再返回；第5分钟横竖屏各切换一次并恢复横屏。单独标注这些操作的时间，确认输入无粘滞、无不合理追赶冻结、RT恢复且可以继续双向穿越。
6. 第10分钟保存结束截图及JSON，重置并确认回到有效检查点。观察几何/纹理/程序数量在相同状态下是否持续增长。

## 判定与证据

中端 Android 目标：代表性场景稳定30FPS、P95约≤33.3ms。真实十分钟运行需要记录每个采样窗口，并说明预热/前后台/方向变化是否被单独标注。CPU帧时间不是GPU时间，不支持GPU计时扩展时写N/A。不能忽略实际崩溃、状态错误或资源持续增长。

将JSON与截图放入 `evidence/device/<型号>/<时间>/`，同时保存环境说明、操作次数、异常复现步骤与验收结论。没有实际文件或没有实际执行的步骤写 NOT RUN；硬件无法连接写 BLOCKED，不能统计PASS。
